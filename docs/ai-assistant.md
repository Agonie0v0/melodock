# AI 音乐助手

在「设置 → AI 助手」填写 OpenAI 兼容 API 地址和 API Key，选择接口类型与代理，获取模型列表后选择模型，也可以手动填写模型 ID。本地无鉴权服务可以不填密钥。配置可以分步保存，启用后补全 API 地址和模型才能执行对话。

支持选择 **Chat Completions**（`/chat/completions`）或 **Responses**（`/responses`）。填写 `https://你的服务商/v1` 等基础地址，或直接粘贴完整接口地址；程序识别末尾接口路径，再按选择的类型发送，获取模型则请求对应前缀下的 `/models`，不会重复拼接路径。Responses 支持图片和工具调用，后续请求会携带工具结果及所需推理上下文。模型必须支持所选接口的工具调用；识别截图还需图片输入能力。

**AI 请求代理** 可选择直连或「使用项目代理」，后者读取「设置 → 音源与下载」中已配置的 HTTP / HTTPS 代理，模型列表、连接测试、网页及聊天渠道的实际 AI 请求都使用同一选择。选择项目代理但未配置地址时会提示补全，不会自动切回直连。代理地址随项目设置实时读取，AI 设置不重复保存凭据。直连模式不读取进程环境变量中的代理。

修改地址、密钥、接口类型或代理后，页面等待 800 毫秒再自动尝试获取模型，连续修改会合并请求；也可点击「获取模型列表」刷新。仅进入或切换页面、保存配置、选择模型不会自动获取，离开页面会取消待执行的请求。此操作不要求先保存、启用 AI 或填写模型；列表是服务商返回的模型 ID，不代表每个模型都支持工具和图片。列表不可用、为空或服务商未实现 `/models` 时，可以手动输入模型 ID。

「测试当前配置」使用表单中尚未保存的地址、模型、接口类型、密钥及代理；密钥留空时沿用服务器已保存值，勾选清除时本次测试不带密钥。测试与获取模型均不保存草稿；保存不需要联网。基础测试只检查文本接口，图片与工具能力需要在对话中验证。接口格式参考 [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Responses 工具调用](https://developers.openai.com/api/docs/guides/function-calling) 和 [模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)。

在主导航打开「AI 助手」，可以直接输入：

- 搜索周杰伦的《晴天》，列出可下载版本。
- 把图片里的歌曲加入本地歌单「通勤」。
- 搜索陈奕迅的《十年》，下载后自动刮削整理入库。
- 查看最近下载任务的进度。
- 查找本地音乐库里的周杰伦，生成整理预览。
- 把本地歌单「通勤」改名为「开车」，移除其中指定歌曲。
- 暂停全部下载，查看失败原因后重试指定任务。
- 将指定歌曲加入收藏，调整播放队列。
- 读取整理预览，按指定候选完成标签修改、归档应用，或恢复指定历史版本。
- 管理 Navidrome 歌单、查看曲库、启动扫描。
- 查看并修改音源、代理、归档或通知配置，清理缓存和运行日志。

助手可发现并调用项目现有的全部 JSON 管理接口，涵盖收藏、播放队列、歌单导入与管理、下载控制、文件标签及删除、整理任务、Navidrome、配置、更新与维护。先查询真实对象和接口参数，再执行操作；保留原接口的路径范围、数据格式、文件锁、版本冲突和 Navidrome 权限检查。密钥、Cookie、鉴权请求头及含凭据的 URL 在发送给模型和写入执行记录前隐藏；修改音源配置时保留隐藏凭据。没有命令行或任意 URL 请求工具。登录接口、对话递归执行入口、媒体字节及事件流不作为管理工具开放。浏览器实际播放、暂停与音量由当前设备控制。

允许操作时，可以直接按明确要求修改配置、移除歌曲、删除文件、应用整理、更新或重启服务；AI 不会因为你仅要求查询就获得修改许可。执行记录会显示调用的具体项目接口及结果。后台任务创建成功不代表任务完成，可让助手继续等待并查询状态；等待时支持停止。

## 在 Telegram / 企业微信中使用

配置好上述模型后，进入「设置 → 通知与机器人」，完成 Telegram 或企业微信自建应用的连接，勾选对应的「使用 AI 对话」并保存。所有渠道的 AI 开关独立，默认关闭。AI 是可选能力：未配置或关闭模型时，普通歌名继续走原搜索流程；“搜索”“下载”“音源”“下一页”等原有命令始终优先，不会被 AI 接管。显式 `/ai` 或图片请求会提示需要启用 AI。

启用后，直接向 Telegram Bot 私聊或企业微信应用发送文字、图片即可调用同一套 AI 音乐工具。Telegram 可给图片附说明，例如「把这些歌加入歌单通勤并下载整理」；企业微信可先发图片识别，再发文字说明目标歌单。Telegram 图片也支持以 PNG / JPEG / WebP 文件发送。每张最大 5 MB。模型需要支持图片输入。

| 命令 | 用途 |
| --- | --- |
| `/ai 搜索晴天，下载后整理入库` | 开始或继续 AI 对话 |
| `/ai_new` | 开始新对话，旧历史在网页保留 |
| `/ai_stop` | 当前操作结束后停止本轮，已加入的下载仍继续 |
| `/ai_status` | 查看本用户 AI 当前执行状态 |
| `/ai_readonly` | 后续轮次仅查询 |
| `/ai_write` | 后续轮次允许操作，仍受网页总开关限制 |
| `/search 歌名 歌手` | 使用原有音乐搜索及选曲按钮 |
| `/status` | 查看本用户下载任务 |

「允许渠道 AI 执行操作」控制所有渠道的写入权限。关闭后，即使用户发送 `/ai_write`，后端也会拒绝所有写入操作，包括歌单、下载、整理、配置修改和删除。权限切换对之后的消息生效；如本轮仍在执行，先 `/ai_stop`。保存机器人配置会请求停止尚未结束的渠道 AI 轮次。

沿用 Telegram 用户白名单和私聊限制、企业微信加密回调与成员权限。对话按渠道和用户隔离，网页管理员可查看历史；音乐库和本地歌单仍是项目共享数据。AI 生成的回复通过原有持久通知队列重试，新建下载关联发起用户，完成后发送音频、文件或链接。复用其他用户已有的下载时，不会转移该下载的管理权。

重复平台回调或服务重启不会自动重跑已经开始的 AI 请求。中断后请核对网页执行记录，再发送下一条需求。长任务不会占住机器人命令入口，可随时查询进度和停止。

图片通过 Telegram `getFile` 或企业微信临时素材接口获取，不跟随消息中提供的任意图片 URL。应用仅持久保存平台媒体 ID，不把图片编码写入对话记录；内置 Telegram 本地 Bot API 服务本身可能缓存接收的文件。自建远程 Bot API 的图片下载需要返回可下载的相对文件路径；内置服务支持读取其受限缓存目录中的绝对路径。

微信入口目前是企业微信自建应用，个人微信、微信群和公众号尚未接入。

## 在飞书、钉钉、Discord 中使用

「更多下载通知渠道」保留原有群 Webhook 功能，独立发送新下载的完成、失败、取消及文件链接，无需配置 AI 或应用凭据。下方「更多对话机器人」增加接收入口；它与 Webhook 分别开关、分别填写凭据，启用其中一项不要求启用另一项。应用机器人也无需 AI：不启用 AI 时仍可发送歌名搜索，使用“下载 1”“音源 2”“下一页”及 `/status` 等命令。

三个新增入口均需要平台可以访问的公网 HTTPS 回调地址及必填的用户白名单。回调及时确认收件，耗时的搜索与 AI 执行在后台进行；结果只发送给发起用户，不发送到配置的群 Webhook。白名单用户共享项目音乐库和歌单，按渠道和用户隔离对话与任务归属。飞书、钉钉目前只接收单聊；群消息被忽略。

### 飞书 / Lark

1. 创建自建应用，启用机器人能力，填写 App ID、App Secret、Verification Token、Encrypt Key，选择国内飞书或国际 Lark。
2. 白名单填写平台的用户 Open ID（`ou_...`），逗号分隔。填写公网访问地址，启用「飞书 / Lark 对话机器人」并保存。
3. 事件与回调选择发送至开发者服务器，地址为 `https://你的域名/bot/feishu`，配置相同 Token 与 Encrypt Key。支持加密的 URL 校验与事件；正式事件必须通过签名校验、时效检查和应用 ID 校验。
4. 订阅 `im.message.receive_v1`，开通接收单聊消息、以应用身份发送消息、获取消息中资源的权限，发布应用并设置可用成员。
5. 单聊发送歌名或命令。不需要 AI；如需自然语言操作或识别图片，再配置模型并打开「飞书 / Lark 使用 AI 对话」。图片通过对应消息的资源接口读取，不使用任意消息 URL。

参考：[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[获取消息中的资源文件](https://open.feishu.cn/document/server-docs/im-v1/message/get-2)。

### 钉钉

1. 创建企业内部应用并开启机器人，填写 Client ID / AppKey、Client Secret / AppSecret、Robot Code。
2. 白名单填写企业成员 UserID（回调中的 `senderStaffId`），逗号分隔；启用「钉钉对话机器人」并保存。
3. 消息接收选择 HTTP 模式，地址为 `https://你的域名/bot/dingtalk`。接收端校验 `timestamp` / `sign`、时间窗口及 Robot Code。
4. 开通企业内机器人发送消息、下载机器人接收文件的权限，发布应用并配置可用成员。
5. 单聊发送文字或命令；可选开启「钉钉使用 AI 对话」后发送歌单图片。图片通过 `downloadCode` 换取平台下载地址，再通过限制公网访问的传输读取。回复使用应用单聊接口，因此后台任务不依赖短期 `sessionWebhook` 的有效期。

参考：[消息发送与接收类型](https://open.dingtalk.com/document/orgapp/receive-message)、[官方机器人 SDK 的图片接收实现](https://github.com/open-dingtalk/dingtalk-stream-sdk-python/blob/main/dingtalk_stream/chatbot.py)。

### Discord

1. 创建 Discord Application 和 Bot，填写数字 Application ID、64 位十六进制 Public Key 与 Bot Token，白名单填写数字用户 ID。
2. 启用「Discord 对话机器人」并保存，在 Developer Portal 设置 Interactions Endpoint URL 为 `https://你的域名/bot/discord`。入口校验 Ed25519 签名、时效及 Application ID，并处理 PING。
3. 将应用安装到服务器，包含 `bot` 和 `applications.commands` scope。保存后点击「注册 Discord /melokeep 命令」；仅创建或更新该命令，不覆盖其他命令，也不会在保存配置时自动注册。
4. 使用 `/melokeep text:晴天 周杰伦` 搜索；`text:/status` 查看任务；`text:下载 1` 下载。配置 AI 并启用渠道 AI 后，可使用 `text:/ai 把这些歌加入通勤歌单`，同时在 `image` 选项附一张图片。
5. 命令的收件确认仅发起用户可见，后续回复与下载链接由机器人私信发送。请允许机器人私信；私信被平台拒绝时会记录日志并重试。此入口使用 Slash Command，不监听普通聊天消息，也不需要 Message Content Intent。

Discord 图片从平台签名回调提供的附件获取，仅允许 Discord 附件 CDN 的 HTTPS 地址，最多 5 MB。临时附件地址会作为收件元数据保存，图片字节不写入历史。若排队或停机导致地址过期，请重新发送图片。

参考：[Discord Interactions 验签](https://docs.discord.com/developers/interactions/overview)、[接收与回复](https://docs.discord.com/developers/interactions/receiving-and-responding)。

飞书、钉钉、Discord 完成下载后通过签名链接交付原文件；Telegram / 企业微信继续按原方式交付音频或文件。通知发送失败会重试，不重新执行 AI 或重新下载音乐。

支持附加一张 PNG、JPEG 或 WebP 图片，每张最大 5 MB。模型先识别歌曲，再查询真实音源并选择匹配版本。模糊歌名、同名或翻唱版本可能需要补充信息。模型识别和版本选择仍可能出错，请查看执行记录中的真实查询及操作结果。

「允许本轮执行项目操作」按轮生效；关闭后后端禁止所有写入工具，只允许查询和等待。开启后支持明确要求的配置修改、应用整理、移除和删除等项目操作。助手只使用项目工具和已注册管理接口，不提供命令行、任意 HTTP 请求或凭据读取能力。

AI 的快捷歌单工具管理 MeloKeep 本地歌单；Navidrome 歌单通过项目操作工具管理。歌曲加入歌单不代表已经下载；下载入队也不代表文件已经入库。可以在执行记录或下载队列查看实际状态。

本批下载指定「整理入库」时，会在下载完成后复用已有刮削归档流水线、资料来源及目录模板，无需修改全局自动整理开关。可信项目自动处理，歧义项留待审核。已存在的下载任务和已下载文件会复用；如需要整理这些文件，查询本地曲库并生成整理预览，在「刮削整理」中审核应用，或明确要求助手核对预览后应用。

对话和工具结果保存在服务器现有数据库中，最多保留 50 个对话，同时最多执行 3 个对话。每轮没有固定总时限、模型请求次数或工具调用次数上限，也不再按可见消息数量阻止继续对话；执行至模型完成、用户停止或实际故障。单次网络请求的连接/读取超时、服务商额度与上下文长度限制仍然生效。停止会等待当前项目操作结束（等待工具可立即停止），并阻止后续工具操作；已经创建的下载和整理任务可以在下一轮要求取消，也可到原工作台管理。服务重启后未完成轮次标记为中断；继续前先查看执行记录，避免重复操作。

文字、图片和执行所需的音乐资料会发送给配置的模型服务。密钥只在服务器保存，配置接口不会回传密钥；服务器数据库及其备份应按私密数据保管。图片仅用于本轮请求，不写入数据库或磁盘历史，模型服务的数据留存取决于其配置。
