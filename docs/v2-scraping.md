# V2 刮削整理功能对照

依据 [Music Tag Web V2 官方文档](https://xiers-organization.gitbook.io/music-tag-web-v2)及公开仓库中的资料源调研，在 MeloKeep 内独立实现刮削整理流程，保留现有 UI 风格、搜索下载和机器人功能。公开仓库默认分支不能据此认定为完整 V2 源码；本实现不依赖激活服务或私有接口，也不宣称与未公开实现逐项相同。

| 工作流 | MeloKeep 中的入口与行为 |
| --- | --- |
| 自动刮削与手动候选 | 按设置中保存的来源查询；审核候选、匹配理由、差异与路径；可修改关键词重新搜索 |
| 丰富资料源 | 网易云、QQ、咪咕、酷狗、酷我；MusicBrainz / Cover Art Archive；AcoustID / Chromaprint 指纹 |
| 批量手动标签 | 17 个文字字段、歌词与封面；手动字段锁定；支持变量赋值及清空全部标签 |
| 批量重命名与目录归档 | 保留旧模板；支持 V2 常用 `${...}` 条件、字符串方法、拼音首字母和计数器；同名保留双方 |
| 提取与预处理 | 自定义文件名提取、空白/水印清理、繁简转换、可逆乱码修复 |
| 歌词与封面 | 内嵌与同名文件、批量导入导出、上传封面与粘贴歌词 |
| 艺术家图片 | 按唯一同名艺术家查询网易云图片，写入音乐库艺术家目录，保护已有图片 |
| 后台刮削 | 可配置多个目录、检查间隔及稳定时间；持久去重；自动应用或只生成预览；可配置未匹配/失败目录，转移可恢复 |
| 重复歌曲检查 | 文件字节、解码音频、元数据三种报告；不自动删除 |
| 音频工具 | 完整解码及参数报告，FFmpeg 转换格式，按 CUE INDEX 01 分轨；预览输出并保留原件 |
| 操作记录 | 全部历史筛选/分页、CSV 报告、候选来源追踪、单曲版本、逐曲或整批恢复、重启回滚 |
| Navidrome 联动 | 已有连接、远程浏览/播放与整理完成后触发扫描继续使用 |

使用方法与依赖见[音乐库使用说明](music-library.md)。默认不自动处理历史曲库，也不会修改未选中的文件。

## 对齐范围和边界

- 功能目标是刮削整理，不包含 V2 的 Subsonic 服务端、网盘音乐服务器、小爱点歌、收听室或商业授权系统。
- 表达式采用受限解释器，不执行任意 Python/Mako 代码；不加载第三方 Python 插件。平台来源已直接集成，不使用其商业插件服务。
- 成功归档使用统一的音乐库及模板；监控识别失败/歧义文件可转移至独立待审核目录，写入阶段失败会回滚当前文件并报告。
- 无真实 AcoustID Key、fpcalc 或外部平台限流时，对应来源会给出任务警告；其他来源仍可使用。没有承诺所有歌曲都能补齐作词、版权、流派、图片和歌词。
- 解码检查不能证明音源是真无损，转码不能改善源音质；没有自动下载替换所谓“更高质量”的原文件。
- 真实生成音频测试覆盖标签写入、导入导出、转码、分轨边界、失败回滚、后续修改保护及原件恢复；网络查询使用模拟测试并辅以公开平台联网验证。未对用户的实际曲库执行操作。
- 本机 Docker daemon 未运行，未执行完整镜像构建；Dockerfile 已加入新模块、Python 依赖及 fpcalc 系统包。
