# 下载、刮削、整理与 Navidrome

musicdl 内置这套功能，运行时不需要 Music Tag Web 容器或激活服务。Music Tag Web V2 是功能参考；本实现没有复制其私有服务，也不代表已实现 V2 全部周边功能。

## 开启自动流程

1. 在「音源与设置 → 刮削、整理与入库」开启「下载后自动刮削」和「下载后自动整理入库」，保存设置。两个开关可独立使用，初始均关闭。
2. 设置整理目录，例如 `library`，实际位置为音乐根目录下的 `/music/library`。目录必须位于音乐根目录内。
3. 选择网易云、QQ 刮削来源，配置歌词、封面保存方式及覆盖规则。复用音源设置中的 Cookie、代理和请求参数；下载来源已有的资料优先使用。
4. 按原方式从搜索、歌单或机器人下载。下载队列显示后续处理状态；在「音乐库 → 刮削与整理」查看候选、标签差异、最终路径及错误。

自动处理优先检查下载来源 ID，再比较标题、歌手、专辑、时长和 Live/Remix 等版本标识。无法确定时保留原文件并进入「待确认」。分数只是匹配依据，不是识别正确率；可选择候选或「保留现有标签」后应用。

默认只补空字段，手动改过的文字字段会锁定。需要覆盖已有标签时打开覆盖规则；锁定的字段仍保留，可在单曲编辑窗口「解除标签锁定」。来源未提供的日期、流派、作曲、专辑歌手等字段不会编造。

默认目录模板为 `{album_artist}/{album}`，文件名为 `{track_number} - {title}`，扩展名自动保留。专辑歌手缺失时用歌曲歌手，缺少曲序时省略序号。多碟可使用 `{album_artist}/{album}/Disc {disc_number}`。支持的变量在设置中显示；不支持 Python 表达式。

## 整理已有音乐

把已有音频放入挂载的音乐目录，在「音乐库 → 本地音乐」刷新并选择歌曲。可以：

- 只刮削、只整理目录，或刮削并整理。
- 批量修改标题、歌手、专辑、专辑歌手、日期、曲序、碟号、流派、作曲、备注，编辑歌词和上传 PNG/JPEG 封面。
- 从「标题 - 歌手」或「歌手 - 标题」文件名提取标签，清理空白及替换文本。
- 检查文件 SHA-256 完全相同的重复文件，生成报告，由用户决定后续处理。

批量操作先生成预览，点击「应用已确认的更改」后才写文件。预览后文件变化会拒绝写入，需重新检查。曲库仍支持搜索、按目录过滤、播放、待播和删除。

MP3、FLAC、M4A、WAV、Ogg、Opus、WMA 已使用生成的真实音频测试文字标签、内嵌歌词和封面，并比较写入前后的解码结果。其他原有格式可继续浏览，能否改写取决于 Mutagen 对具体容器的支持。普通标签处理不转码。没有音频指纹、音频内容去重、自动质量升级、CUE 分轨或繁简转换。

## 文件保护与恢复

每个文件使用稳定 ID。整理后更新播放、收藏、歌单、下载记录及签名链接的引用，旧路径链接可继续解析；不要手工删除数据库来重建索引。

- 下载中：`/music/.partial`；开启自动整理后，交接文件位于 `/music/.processing`。
- 最终曲库：默认 `/music/library`。
- 操作备份：`/music/.musicdl-history`，保存修改前的完整音频和同名附属文件。

内部目录不会出现在本地曲库扫描中。任务历史支持恢复原标签、原名及目录；自动任务的原目录可能是 `.processing`。恢复会检查音频以及歌词、封面是否有后续变化，存在冲突时保留当前文件并提示处理。服务重启会尝试回滚未完成的文件发布，任务转为暂停，可重新检查。

默认备份保留 7 天，可配置 1–365 天；过期备份在服务启动时清理，过期后无法通过任务恢复。处理期间需要额外磁盘空间保存原件及工作副本，备份目录与数据库都应纳入 NAS 备份。文件发布使用同目录临时文件、原子替换和排他硬链接；不支持硬链接的文件系统会使移动发布失败并保留原件。目标重名自动追加序号；不会直接覆盖另一首歌。

后台按单队列处理文件，可取消后续文件；当前文件先完成或回滚。单批最多 1000 个文件；现有记录查询仍有 10000 条上限，尚未针对超大曲库做性能承诺。机器人和通知等待自动处理结束；待确认、失败或暂停时仍可取回已下载文件。

## 连接 Navidrome

在「音源与设置 → Navidrome 连接」填写地址、用户名与密码，或者服务支持的 API Key，启用并「保存并测试连接」。密码和 API Key 保存在服务端数据库中，浏览器读取配置只返回是否已保存；媒体链接不包含认证信息。留空保留原凭据，勾选清除后保存可移除旧凭据。

「音乐库 → Navidrome」支持专辑分页与排序、歌手浏览、歌曲和专辑搜索、封面、在线播放和加入待播。无需把 Navidrome 数据库导入 musicdl。本地文件和远程文件分开管理，远程歌曲不提供本地删除操作。

「整理完成后自动触发扫描」需要 Navidrome 与 musicdl 访问同一最终目录，并且账号有扫描权限。也可在 Navidrome 页面手动扫描。触发扫描不等于服务已完成索引；扫描失败会显示提示，本地入库结果保留。

现有 Navidrome 可把宿主机 `./music/library` 挂载为其音乐目录。musicdl 单独部署不要求同时安装 Navidrome；如需一起运行，可参考 [Compose 示例](../docker-compose.navidrome.yml)：

```sh
docker compose -f docker-compose.navidrome.yml up -d --build
```

示例从当前源码构建 musicdl，避免误用尚未发布这些功能的 `latest` 镜像。访问 Navidrome 的 `4533` 端口完成初始化，在 musicdl 中填写 `http://navidrome:4533`，用创建的账号连接。两个服务通过共享最终目录联动，不需要 Music Tag 服务。

测试使用了模拟的 OpenSubsonic HTTP 服务验证认证、专辑浏览、Range 播放和扫描；没有使用你的真实 Navidrome 服务、凭据或曲库。部署后需用实际地址进行连接测试。
