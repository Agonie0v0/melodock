# 下载、刮削、整理与 Navidrome

MeloDock 内置这套功能，运行时不需要 Music Tag Web 容器或激活服务。Music Tag Web V2 是功能参考；本实现没有复制其私有服务，也不代表已实现 V2 全部周边功能。

## 页面分工

- **歌单**：我的歌单、我的收藏、歌单导入。
- **音乐库**：本地音乐与 Navidrome 的浏览、筛选和播放；选曲后可送往刮削整理。
- **刮削整理**：选择与处理、任务与审核；标签编辑、重命名、音频工具和恢复操作集中在这里。
- **设置**：音源与下载、刮削与归档默认规则（含来源、监控和指纹配置）、Navidrome 连接、通知与机器人。右上角主题图标可选择浅色、深色或跟随系统，偏好自动保存。

工作台仅保留处理范围、本次操作和生成预览；资料来源、覆盖规则、歌词封面和归档模板统一在设置中修改，工作台显示只读摘要。各栏目独立记住当前子页。顶部导航可以拖动排序，也可点击「调整导航顺序」使用前移/后移按钮，支持手机操作；顺序自动保存在当前浏览器。

## 开启自动流程

1. 在「设置 → 刮削与归档」开启「下载后自动刮削」和「下载后自动整理入库」，保存设置。两个开关可独立使用，初始均关闭。
2. 设置整理目录，例如 `library`，实际位置为音乐根目录下的 `/music/library`。目录必须位于音乐根目录内。
3. 从网易云、QQ 音乐、咪咕、酷狗、酷我、MusicBrainz、AcoustID 中选择资料源，配置歌词、封面保存方式及覆盖规则。平台资料请求复用音源设置中的 Cookie、代理和请求参数；下载来源已有的资料优先使用。默认只选网易云与 QQ，按需要启用其他来源。
4. 按原方式从搜索、歌单或机器人下载。下载队列显示后续处理状态；在「刮削整理 → 任务与审核」查看候选、标签差异、最终路径及错误。

自动处理优先检查下载来源 ID，再比较标题、歌手、专辑、时长和 Live/Remix 等版本标识。无法确定时保留原文件并进入「待确认」。分数只是匹配依据，不是识别正确率；可选择候选或「保留现有标签」后应用。

默认只补空字段，手动改过的文字字段会锁定。需要覆盖已有标签时打开覆盖规则；锁定的字段仍保留，可在单曲编辑窗口「解除标签锁定」。来源未提供的日期、流派、作曲、专辑歌手等字段不会编造。

默认目录模板为 `{album_artist}/{album}`，文件名为 `{track_number} - {title}`，扩展名自动保留。专辑歌手缺失时用歌曲歌手，缺少曲序时省略序号。多碟可使用 `{album_artist}/{album}/Disc {disc_number}`。同时支持 V2 常用的 `${...}` 条件与字符串表达式，见下文。

## 资料来源与覆盖范围

下载音源与刮削来源独立。资料来源列表由后端返回，界面展示来源网站、可补字段和限制。

| 来源 | 资料范围 | 限制 |
| --- | --- | --- |
| 网易云 | 歌名、歌手、专辑、部分日期/曲序/碟号、封面、歌词 | 复用平台 Cookie 和代理；具体字段取决于平台返回 |
| QQ 音乐 | 歌名、歌手、专辑、部分日期/曲序/碟号、封面、歌词 | 复用平台 Cookie 和代理；具体字段取决于平台返回 |
| 咪咕、酷狗、酷我 | 歌名、歌手、专辑、封面与歌词 | 只请求资料接口，不解析音频地址；平台可能限流或缺少字段 |
| MusicBrainz | 录音及发行版本、专辑歌手、发行日期、曲序、碟号 | 无需账号，限速每秒一次；国际社区资料可能不完整，不提供歌词 |
| Cover Art Archive | 所选 MusicBrainz 发行版本的封面 | 随 MusicBrainz 使用，仅在该版本标记有正面封面时下载 |
| AcoustID | 通过 Chromaprint 音频指纹识别 MusicBrainz 录音及发行候选 | 需要 fpcalc 和 AcoustID 应用 Key；不上传音频，不提供歌词；同一录音的多个发行仍需审核 |

MusicBrainz 遵循其[官方 API](https://musicbrainz.org/doc/MusicBrainz_API)查询录音和发行版本，不进行音频解析。网络请求复用全局代理（代理范围需设为全部）。同专辑的多个发行版本、专辑不符、版本不符或低匹配分数进入人工审核；不能保证每首歌的作曲、流派、歌词和封面都能补齐，不会编造资料。

识别时优先采用文件内已有标签及人工修改，避免旧下载记录覆盖当前歌曲身份。手动刮削会查询所选来源，即使保留了原下载来源也会提供其他候选；自动下载任务优先使用可靠的原始来源资料。原下载来源不支持补充详情时，也会查询配置的刮削来源。只有标题、歌手、专辑及版本匹配且无歧义时，才从另一候选补充缺失资料；任务中逐字段标出补充来源，不会把不同专辑或不同 Live/Remix 版本混在一起。单个来源失败或无结果会记录在任务中，其他来源仍可继续。每个任务保存创建时的来源与覆盖规则，更改全局设置不影响已有预览。

## 整理已有音乐

把已有音频放入挂载的音乐目录，打开主导航「刮削整理 → 选择与处理」。在下方选曲，选择本次处理方式后点击「生成修改预览」，进入「任务与审核」确认标签和目录。刮削来源及覆盖规则从已保存设置读取，任务创建后保留规则快照；歌曲筛选变化时清空选择，避免处理隐藏的文件。也可在「音乐库 → 本地音乐」选中歌曲后点击「送往刮削整理」，保留选择进入工作台。音乐库页面不再直接执行标签或目录修改。可以：

- 只刮削、只整理目录，或刮削并整理。
- 批量修改标题、歌手、专辑、专辑歌手、日期、曲序、碟号、流派、作曲、备注，编辑歌词和上传 PNG/JPEG 封面。
- 同时支持作词、语言、版权、发行商、分组、BPM、ISRC；单曲编辑和批量编辑均保存可恢复版本。
- 按变量批量编辑标签或只重命名，支持「标题 - 歌手」「歌手 - 标题」和自定义文件名提取模板。
- 清理空白、指定文本替换/水印移除、繁简转换、可逆的 UTF-8 被按 Latin1 误读修复；不会猜测并覆盖无法逆转的乱码。
- 导出内嵌歌词为同名 LRC、把同名 LRC 嵌入音频、导出内嵌封面、导入同名图片或目录 `cover.jpg` / `cover.png`。
- 清空全部标签（包括自定义标签）、内嵌歌词及封面，保留同名附属文件。原件仍可从历史恢复。
- 查找文件 SHA-256 相同、解码音频相同或标题/歌手/时长相同的重复候选，生成报告，由用户比较和删除。
- 音频完整解码检查、音频参数报告、格式转换与 CUE 分轨。
- 刮削单一艺术家图片到音乐库的艺术家目录；来源为网易云，要求唯一的同名匹配。已有 `artist.jpg` / `artist.png` 保留，不覆盖。

批量操作先生成预览，点击「应用已确认的更改」后才写文件。预览后文件变化会拒绝写入，需重新检查。曲库仍支持搜索、按目录过滤、播放、待播和删除。

MP3、FLAC、M4A、WAV、Ogg、Opus、WMA 已使用生成的真实音频测试文字标签、内嵌歌词和封面，并比较写入前后的解码结果。其他原有格式可继续浏览，能否改写取决于 Mutagen 对具体容器的支持。普通标签处理不转码。完整性检查只验证可解码及读取参数，不宣称能鉴定假无损或提升音质。

## 变量与文件名规则

保留旧的 `{title}` 语法，同时支持 `${title}`、`${artist}`、`${albumartist}`、`${tracknumber}`、`${discnumber}`、`${year}`、`${first_artist}`、`${first_artist_letter}`、`${filename}`、`${file_song_name}`、`${parent_path}`、`${parent_parent_path}`、`${lyrics}`、`${counter}` 和 `${null}`。`parent_path`、`parent_parent_path` 返回目录名；计数器从本批次 1 开始，艺术家首字母使用拼音。文字标签名称也都可作变量。

批量标签编辑始终基于每首歌曲修改前的快照计算，避免字段之间的覆盖顺序影响结果。例如把专辑歌手复制到歌手：`${albumartist or artist}`。文件名示例：

```text
${discnumber.zfill(2) + '_' if discnumber and tracknumber else ''}${tracknumber.zfill(2) + '. ' if tracknumber else ''}${title} - ${artist.split('/')[0].strip()}
```

支持字符串拼接、`if ... else ...`、`and` / `or` / `not`、`str()` / `int()`、字符串 `strip` / `replace` / `split` / `lower` / `upper` / `title` / `zfill` 及整数下标。表达式通过限定语法树解释，不执行 Python 代码，也不支持导入、文件访问、任意属性、循环或完整 Mako。单个变量/表达式结果上限 10000 字符，数值参数上限 1000；路径结果会清理非法字符和保留名。

自定义提取模板示例：`{track_number} - {artist} - {title}`。模板必须包含标签变量，每个变量最多出现一次；分隔符按普通文本匹配，不执行正则或脚本。

## 目录监控与指纹识别

在「设置 → 刮削与归档 → 目录监控与预处理」启用监控，每行配置一个目录（默认 `incoming`），保存。默认每 180 秒检查，连续两次检查文件大小及修改时间保持稳定、且观察时间至少 30 秒才提交。监控目录必须位于允许的挂载根目录中，并与最终音乐库分开。可以立即检查已保存的目录或读取上次检查状态。

可选择自动应用可靠匹配，或只生成预览。无法确定歌曲/发行版本或识别失败时，在「任务与审核」中处理；可额外配置独立的未匹配/失败目录，转移也保存可恢复记录，留空则保留原处。应用阶段写入失败会回滚当前文件并报告错误，不自动删除失败文件。检查结果及已提交的文件版本持久化，重启后不会重复提交相同版本；改变过的文件可重新处理。转码/分轨输出目录不参与监控导入。

AcoustID 需要在「音频指纹识别」保存[应用 Key](https://acoustid.org/new-application)，或者通过环境变量 `MELODOCK_ACOUSTID_KEY` 提供。配置读取只返回是否存在 Key，不返回内容。来源中勾选 AcoustID 后优先计算前 120 秒指纹，唯一的高置信录音可为其他来源提供搜索关键词；多个发行候选仍进入审核。原生安装还需安装 `fpcalc`，可用 `MELODOCK_FPCALC` 指定可执行文件路径；Docker 镜像已安装 `libchromaprint-tools`。

## 音频检查、转码与分轨

在文件列表「更多管理操作」选择检查方式或转换工具。重复检查不删除文件：字节去重包含标签，音频去重比较统一为 44.1 kHz 双声道 PCM 后的 SHA-256，标题/歌手/时长只用于发现疑似重复，不能证明同一版本。音频完整性检查会完整解码首个音轨，报告错误、时长、码率、采样率、声道和可读取的位深。

转换输出支持 FLAC、MP3、M4A/AAC、Opus、WAV。预览列出输出路径，确认后生成 `原文件名 - converted` 目录；CUE 分轨生成 `原文件名 - tracks` 目录。原件始终保留，输出重名追加序号。转码继承文字标签、封面与歌词；分轨继承专辑、艺术家及 CUE 曲序/标题，不把整轨歌词时间轴直接复制到每个分轨。

CUE 可在窗口粘贴，或使用音频旁的同名 `.cue`，支持 UTF-8 和 GB18030、多 FILE、INDEX 01，最多 1000 轨、1 MB。每个选中音频只处理与其文件名对应的 FILE 段，检查边界递增且不超过音频时长；不读取 CUE 指向的其他路径。需要服务器 FFmpeg，可通过 `MELODOCK_FFMPEG` 指定路径；Docker 镜像已包含。MP3 采样率不高于 48 kHz，Opus 使用其支持的采样率。

任务详情可导出 UTF-8 CSV 报告，包含标签前后值、路径、输出文件、检查参数及错误。任务筛选在服务端对全部历史进行，再分页；单曲可查看标签版本并恢复到指定修改前。恢复旧版本前需先处理其后续修改。

## 文件保护与恢复

每个文件使用稳定 ID。整理后更新播放、收藏、歌单、下载记录及签名链接的引用，旧路径链接可继续解析；不要手工删除数据库来重建索引。

- 下载中：`/music/.partial`；开启自动整理后，交接文件位于 `/music/.processing`。
- 最终曲库：默认 `/music/library`。
- 操作备份：`/music/.musicdl-history`，保存修改前的完整音频和同名附属文件。

内部目录不会出现在本地曲库扫描中。任务历史支持恢复原标签、原名及目录；自动任务的原目录可能是 `.processing`。恢复会检查音频以及歌词、封面是否有后续变化，存在冲突时保留当前文件并提示处理。服务重启会尝试回滚未完成的文件发布，任务转为暂停，可重新检查。

默认备份保留 7 天，可配置 1–365 天；过期备份在服务启动时清理，过期后无法通过任务恢复。处理期间需要额外磁盘空间保存原件及工作副本，备份目录与数据库都应纳入 NAS 备份。文件发布使用同目录临时文件、原子替换和排他硬链接；不支持硬链接的文件系统会使移动发布失败并保留原件。目标重名自动追加序号；不会直接覆盖另一首歌。

后台按单队列处理文件，可取消后续文件；当前文件先完成或回滚。单批最多 1000 个文件；现有记录查询仍有 10000 条上限，尚未针对超大曲库做性能承诺。机器人和通知等待自动处理结束；待确认、失败或暂停时仍可取回已下载文件。

## 连接 Navidrome

在「设置 → Navidrome 连接」填写地址、用户名与密码，或者服务支持的 API Key，启用并「保存并测试连接」。密码和 API Key 保存在服务端数据库中，浏览器读取配置只返回是否已保存；媒体链接不包含认证信息。留空保留原凭据，勾选清除后保存可移除旧凭据。

「音乐库 → Navidrome」支持专辑分页与排序、歌手浏览、歌曲和专辑搜索、封面、在线播放和加入待播。无需把 Navidrome 数据库导入 MeloDock。本地文件和远程文件分开管理，远程歌曲不提供本地删除操作。

「整理完成后自动触发扫描」需要 Navidrome 与 MeloDock 访问同一最终目录，并且账号有扫描权限。也可在 Navidrome 页面手动扫描。触发扫描不等于服务已完成索引；扫描失败会显示提示，本地入库结果保留。

现有 Navidrome 可把宿主机 `./music/library` 挂载为其音乐目录。MeloDock 单独部署不要求同时安装 Navidrome；如需一起运行，可参考 [Compose 示例](../docker-compose.navidrome.yml)：

```sh
docker compose -f docker-compose.navidrome.yml up -d --build
```

示例从当前源码构建 MeloDock，避免误用尚未发布这些功能的 `latest` 镜像。访问 Navidrome 的 `4533` 端口完成初始化，在 MeloDock 中填写 `http://navidrome:4533`，用创建的账号连接。两个服务通过共享最终目录联动，不需要 Music Tag 服务。

测试使用了模拟的 OpenSubsonic HTTP 服务验证认证、专辑浏览、Range 播放和扫描；没有使用你的真实 Navidrome 服务、凭据或曲库。部署后需用实际地址进行连接测试。

## 收藏与歌单

主导航统一为「歌单」，内含「我的歌单」「我的收藏」「歌单导入」。其中「我的收藏」用于一键保存喜欢的单曲；「我的歌单」用于自建主题歌单及保存导入的外部歌单；「歌单导入」负责导入平台歌单。切换时仍保留各自记录，收藏不会自动复制到歌单。正在播放的待播队列继续独立管理。


## Navidrome 歌曲与歌单

「音乐库 → Navidrome」默认展示全部歌曲，可切换到专辑或歌手；全部歌曲分页读取。三种分类都支持卡片/列表切换，分类和显示方式保存在当前浏览器。搜索仍支持歌曲与专辑。

连接并启用 Navidrome 后，进入「歌单 → 我的歌单」会自动读取当前账号可访问的远程歌单，并每 60 秒刷新。无需逐个粘贴链接导入。远程歌单标记为 Navidrome，打开时读取最新曲目，可直接播放、收藏和加入待播；名称及曲目增删在 Navidrome 中管理。远程歌单不会重复复制成本地歌单，不会修改本地自建/平台导入歌单。可点击「同步歌单」立即刷新；连接失败会显示原因并保留当前页面的上次结果，重新连接后可重试。

全部歌曲使用 [OpenSubsonic search3 空查询](https://opensubsonic.netlify.app/docs/endpoints/search3/)分页读取，歌单使用 [getPlaylists](https://opensubsonic.netlify.app/docs/endpoints/getplaylists/)及 getPlaylist；认证信息保留在服务端。

播放 Navidrome 歌曲时优先通过 [getLyricsBySongId](https://opensubsonic.netlify.app/docs/endpoints/getlyricsbysongid/)读取该歌曲的同步歌词，保留毫秒时间及偏移；旧服务器不支持时回退到 getLyrics。本地音乐优先读取同名 `.lrc`，其次读取内嵌歌词，支持 ID3 SYLT 毫秒同步歌词。同步歌词支持跟随进度和点击跳转；纯文本歌词可调整字号和手动滚动，没有时间轴时禁用跟随。正在播放页提供音量滑块、静音和音量百分比，底部三个操作按钮等宽并与播放面板对齐。
